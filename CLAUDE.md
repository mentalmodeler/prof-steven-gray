# CLAUDE.md

Content and site variants for Dr. Steven Gray's Human-Environment Interactions Lab.
All site content lives in one JSON file. Visual variants are generated from it. Hosted on GitHub Pages
straight from the repo root (no build step on the server).

## Layout

```
content/
  site-content.json          THE DATA. The only file edited for content changes
  site-content.schema.json   JSON Schema 2020-12; each property's `description` is its field-level instruction
  site-content.js            GENERATED by `npm run validate` (window.SITE_CONTENT). Never hand-edit. Commit it.
  AGENT-GUIDE.md             Editing rules and recipes (add publication/person/news/funding/tag). Read before editing data.
  SCHEMA-SUMMARY.md          Readable summary of the schema
  EXTRACTION-ISSUES.md       Problems in the original site awaiting Dr. Gray's decision
scripts/
  validate.mjs               Schema + integrity checks, then regenerates site-content.js
  one-time-import/           Provenance only: the extractor from the old index.html. Do not run.
variants/
  variants.js                Registry: [{id, label, default}]. Exactly one default. Edit by hand
  concept-map/               index.html + style.css + app.js, rendered entirely from the data
img/, favicon.*              Static assets referenced by the data (`photo.src`, image blocks)
index.html                   Redirects to the default variant (keeps ?filters and #hash)
```

## Commands

- `npm install` once, then `npm run validate` after **every** data edit. It must print `OK`; it also regenerates
  `content/site-content.js`. A stale `site-content.js` means pages opened from disk show old content, and
  GitHub Pages serves it too, so commit the regenerated file with the JSON.
- Preview: `python3 -m http.server` from the repo root, then open `/variants/concept-map/`. Opening the
  variant's `index.html` directly from disk also works (it falls back to the embedded `site-content.js`).

## Design decisions (the non-obvious ones)

- **Content only, no presentation.** The schema holds data plus loose structure (`sections[]` order and
  `visible`, `includes`). Columns, numbering, colors, animation belong to variants.
- **`news` is top-level, not a section.** Home shows it via `sections[home].includes: ["news"]`. `includes` is
  structure ("this section shows these blocks by default"), not layout; variants may place it differently.
- **Publications are structured**, not citation strings, so they can be filtered (year, type, tag, author,
  student/undergraduate role, status). `citationOverride` is a last-resort escape hatch. Tags and types are
  controlled vocabularies in the data; add the vocabulary entry before using it.
- **Rich text is `blocks[]`** (paragraph | images) with a restricted inline markdown subset
  (`*italic*`, `**bold**`, `[label](url)`, `\*`). Raw HTML is rejected by the validator.
- **Ids are permanent** kebab-case; array order is display order. Source typos were kept verbatim.
- **`role` on people** is displayed text (e.g. "PhD, 2015") and duplicates `degree`/`graduationYear`;
  the validator does not cross-check them.
- `teaching` is `visible: false` (it was commented out in the original site).

## GitHub Pages constraints

- Served from the repo root; site may live under `/prof-steven-gray/`, so **all URLs must be relative**.
  Never use root-absolute paths like `/img/x.png`.
- `.nojekyll` is present; keep it so Pages serves files as-is.
- Anything the site needs at runtime must be committed (no server-side build): `site-content.js`, images, assets.
- Variants may use CDN fonts/scripts, but keep content rendering free of build tooling.

## Variants and routes

Each variant is a real path: `/variants/<id>/`. `/` is the stable URL: it redirects to whichever variant has
`default: true` in `variants/variants.js`, keeping the query string and hash. To change what `/` shows, move
`default: true` to another entry. The query string belongs to the publication filters (`topic`, `year`, `type`,
`author`, `students`, `q`); there is no `?variant=`. Keep those param names the same across variants.
(`variants.js` is a script rather than JSON so it also works when opened from disk, where `fetch` is blocked.)

## Adding a variant

Create `variants/<id>/` with its own `index.html`, CSS and JS; load `../../content/site-content.js` and
resolve image paths relative to the repo root (see `ROOT` in `variants/concept-map/app.js`). Render everything
from `window.SITE_CONTENT`: don't copy text into the HTML. Respect `sections[].visible` and `news.visible`.
Add `{ id, label }` to `variants/variants.js`. The concept-map variant shows the full pattern, including
URL-synced publication filters. Shared helpers (inline markdown, blocks, data loading, filter state) currently live
only in concept-map's `app.js`; when a second variant exists, extract them to `variants/_shared/`.
